## กติกาการซอย
- **Story** = ส่วนที่ส่งมอบคุณค่าให้ผู้ใช้ปลายทางได้ BA/QA ทดสอบบน UAT แล้ว sign-off · AC เขียนเป็นภาษาที่ BA อ่านเข้าใจ (สิ่งที่เห็นหรือทำได้ ไม่ใช่ชื่อคลาส) แบบ Given / When / Then
- **Task** = งานเทคนิคภายใน (โครงโปรเจกต์, infra, refactor) จบเมื่อผ่าน AC ของตัวเอง · AC เขียนเชิงเทคนิคได้
- ต้องมี Story อย่างน้อย 1 ใบ · ซอยตามฟีเจอร์ที่ส่งมอบได้ (vertical slice) ไม่ซอยตามชั้นของโค้ด
- แต้ม (ขนาดงาน ไม่ใช่คุณค่า) ใช้ 1, 2, 3, 5, 8 และไม่เกิน {{MAX_POINTS}} ถ้าใหญ่กว่านั้นให้ซอยเป็นการ์ดเล็กที่ยังส่งมอบได้ · ขั้นตอนย่อยภายในการ์ดใส่ใน `subtasks` (ไม่มีแต้ม)
- การ์ดหนึ่งใบทำใน repo เดียว เลือกจาก: {{REPOS}}
- `model`/`effort` = model ที่ Claude ควรใช้ทำ spec และ review ของการ์ดนั้น (haiku / sonnet / opus และ low / medium / high) ตามความยากและความเสี่ยง
- `scope_hint` = path หรือ glob ใน repo ของการ์ดที่มีอยู่จริง ไฟล์หรือโฟลเดอร์ใหม่ให้ขึ้นต้นด้วย `new:` (arbiter ตรวจว่ามีอยู่จริง)
- `epic`: ถ้ามี epic เดิมใน KS ที่ตรงให้ใส่รหัสการ์ด (string) ไม่มีให้เสนอใหม่ {"title", "goal"} · `release` ตั้งชื่อตามฟีเจอร์หรือ milestone ห้ามใช้เลขเวอร์ชันของ service
- `depends` = id ของการ์ดที่ต้องเสร็จก่อน
