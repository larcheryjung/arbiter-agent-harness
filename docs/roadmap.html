Roadmap

ตอนนี้

  • ใช้ /feature กับการ์ดจริงให้ครบ 10 ใบ (ถัดไป: KS-166) · retro ทุกใบลง LESSONS.md
  • ลองให้ Gemini Pro ลงมือแทน Flash ในการ์ดถัดไป แล้วเทียบจำนวนรอบที่ถูกตีกลับกับ KS-160

ค้างจาก SPIKE-1 / KS-160 (เล็ก ทำเมื่อเจอซ้ำ)

  • spike รับไฟล์แนบที่เป็นข้อความทั่วไป (.html, โค้ด)
  • เก็บประวัติ questions.md ทุกรอบ · Claude อ้างไฟล์ด้วย path เต็ม
  • สคริปต์ต่อ DB ที่อ่านรหัสจาก env แทนให้ AI เปิดไฟล์ .secret
  • แก้คำสั่ง move-to-board.ps1 -IssueKeys @(...) ใน AGENTS.md ของ kong-command-center (ใช้ไม่ได้เมื่อส่งหลายใบ)

ถัดไป (มีตัวกระตุ้น)

อะไรทำเมื่อ
/poc ลองของบน spike/* ห้าม merge ผลเป็น note ให้ spike อ่านต่อมีการ์ด POC จริงใบแรก (แบบอยู่ใน docs/spike-design.md ข้อ 6)
/quick งาน ≤2 ไฟล์ · spec สั้น → เทสต์ fail ก่อน → แก้ → review · Gate 2 จุดเดียว/feature หนักเกินกับงานเล็กจริง
Ops: runbook → dry-run → คนอนุมัติ → post-check → rollbackมีการ์ด deploy หรือ DB จริง
ให้ reviewer รันคำสั่งพิสูจน์เองใน worktree แยกdispute ถูกใช้บ่อยจนเป็นภาระ

ภายหลัง

  • pip install -e + shim hook ที่ fail-closed (ตอนนี้ย้ายโฟลเดอร์แล้ว hook หายเงียบ)
  • เก็บหลักฐานใน .git/arbiter/ · approve ต้องใช้รหัสที่คนเห็นเท่านั้น
  • CI ตรวจ trailer Arbiter-Tree เพื่อปิดช่อง --no-verify
  • pre-push และ Claude hook กัน HBS DB / prod
  • pack jira-ks · ตรวจ transcript ของ Gemini อัตโนมัติว่าส่งคำพูดคุณตรงไหม

ไม่ทำ (จนกว่าจะมีเหตุ)

/greenfield · migration · ให้ Claude คุมงานแทน Gemini · dashboard · ชุดทดสอบพฤติกรรมโมเดล

คำถามที่ยังค้าง

  • ใครเขียน AC: คุณเขียนเอง หรือ Claude ร่างแล้วคุณอนุมัติที่ Gate 1 (ตอนนี้เป็นแบบหลัง)
  • จะให้คนอื่นในทีมใช้ด้วยหรือไม่ ถ้าใช่ คู่มือนี้คือจุดเริ่ม

ดูแลคู่มือนี้

คู่มืออยู่ที่ docs/ ของ repo arbiter: assets/style.css และ assets/site.js ใช้ร่วมกันทุกหน้า สารบัญและปุ่มก่อนหน้า / ถัดไปสร้างจากรายการใน site.js ทุกครั้งที่ขึ้นเวอร์ชัน ให้อัปเดตหน้านี้ ตัวเลขในหน้าแรก บรรทัด v0.x.y ใน nav ทุกหน้า และหน้าที่เกี่ยวข้องกับสิ่งที่เปลี่ยน
