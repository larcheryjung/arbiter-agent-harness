บทที่ 4 · เรียนตามลำดับ

เมื่องานติด

งานติดได้ 3 แบบ: งานยังไม่ดีพอ (แก้แล้วจบ), spec ผิดเอง (แก้งานอย่างไรก็ไม่จบ) และ AI สองฝั่งเห็นไม่ตรงกัน Arbiter มีทางออกให้ทุกแบบ โดยหลักคือ deadlock ต้องจบด้วย หลักฐานจากเครื่อง หรือ คำตัดสินของคุณ ไม่ใช่ให้ AI สองตัวเถียงกันเป็นข้อความ

แผนที่: เห็นอะไร แล้วทำอะไร

เห็นแปลว่าใครทำต่อ
FAILเครื่องตรวจหรือ Claude ตีกลับGemini แก้เอง คุณไม่ต้องทำอะไร
ESCALATEตีกลับครบ 2 รอบ, gate ครบ 6 รอบ หรือ dispute ครบ 2 ครั้งคุณ: ทำต่อ: … / แก้ spec: … / พักการ์ด
SPEC_ISSUEปัญหาอยู่ที่ spec (Claude เสนอแก้มาให้)คุณ: แก้ spec ตามที่เสนอ หรือ ทำต่อ: …
DISPUTE_UPHELDArchitect ยืนตาม finding เดิม และบอกทางที่ทำได้Gemini แก้ต่อ (คุณทักได้ถ้าไม่เห็นด้วย)
NEEDS_DECISIONตัดสินจากหลักฐานไม่ได้ เป็นเรื่องธุรกิจหรือทางเลือกที่ถูกทั้งคู่คุณ เลือกทาง
STALEไฟล์งานเปลี่ยนหลังรีวิวผ่านคุณ ดูว่าใครแก้ แล้วสั่ง review ใหม่
BLOCKEDทำขั้นนี้ไม่ได้ (ยังไม่ผ่าน Gate 1, spec ถูกแก้, การ์ดถูกพัก, ไม่มีไฟล์เปลี่ยน)อ่านเหตุผล แล้วทำตาม ▶
ERRORระบบมีปัญหา (Claude อ่าน Jira ไม่ได้, ตอบผิดรูปแบบ, git ไม่ผ่าน)ถ้าไม่เข้าใจ ถาม Claude Code อย่าให้ Gemini เดา
PARKEDการ์ดถูกพักกลับมาด้วย ทำการ์ด KS-xx ต่อ

FAIL: วงจรปกติ

FAIL เป็นเรื่องปกติ Gemini แก้เองแล้วรัน review ใหม่โดยคุณไม่ต้องทำอะไร ตั้งแต่รอบที่ 2 Claude ตรวจเฉพาะข้อเดิมและสิ่งที่พังเพิ่ม ระบบจะส่งเรื่องให้คุณเมื่อถึงเพดานใดเพดานหนึ่ง:

เพดานค่าconfig
Claude ตีกลับ2 รอบmax_rejections
รัน gate6 รอบmax_gate_runs
dispute2 ครั้งต่อการ์ดmax_disputes

เมื่อคุณอนุมัติ spec ใหม่ (Gate 1 ใหม่) เพดานตีกลับและ gate นับใหม่ เพราะถือเป็นสัญญาฉบับใหม่

ESCALATE: คุณมี 3 ทาง

ทำต่อ: <คำตัดสิน>

เช่น ทำต่อ: ใช้ inline examples ได้ ไม่ต้องอ้างไฟล์
Gemini รัน review --continue เพดานรีเซ็ต และคำตัดสินถูกบันทึกลง decisions.md ซึ่ง reviewer ต้องยึด

แก้ spec: …

เช่น แก้ spec: เปลี่ยน AC11 เป็น…
Gemini ส่งด้วย answer Gate 1 เดิมถูกยกเลิก Claude แก้ spec แล้วคุณอนุมัติ Gate 1 ใหม่

พักการ์ด

Gemini รัน park งานอยู่ครบ ระหว่างพักจะ review หรือ commit ไม่ได้ กลับมาด้วย ทำการ์ด KS-xx ต่อ

เลือกทางไหนดี ถ้าเรื่องที่ติดไม่ได้ทำให้ spec ผิด แค่ต้องมีคนตัดสิน เลือก ทำต่อ พร้อมเขียนคำตัดสินให้ชัด ถ้าสิ่งที่เขียนใน spec ทำไม่ได้หรือไม่ใช่สิ่งที่ต้องการแล้ว เลือก แก้ spec คำว่า "ทำต่อ" เฉยๆ โดยไม่มีคำตัดสิน มักทำให้วนรอบเดิม

decisions.md: คำตัดสินของคุณผูกมัด reviewer

ทุกครั้งที่คุณพิมพ์ "ทำต่อ: …", "พักการ์ด" หรือ "ทำการ์ดต่อ" arbiter บันทึกคำพูดของคุณลง .arbiter/tasks/KS-xx/decisions.md ตามตัวอักษร prompt ของ reviewer และของ Architect ตอนชี้ขาด dispute สั่งให้:

  • อ่านไฟล์นี้ทุกครั้ง
  • ถือว่าคำตัดสินของคุณมีผลเหนือ spec ในเรื่องที่พูดถึง
  • ห้ามตีกลับเรื่องที่คุณตัดสินแล้ว

ก่อน v0.3.3 คำตัดสินเหล่านี้อยู่แค่ใน state.json ซึ่ง reviewer มองไม่เห็น เป็นสาเหตุหลักที่ KS-160 วน 3 รอบ

SPEC_ISSUE: เมื่อ spec ผิดเอง

reviewer มีคำตัดสินได้ 3 แบบ: PASS, FAIL และ SPEC_ISSUE ใช้เมื่อปัญหาอยู่ที่ spec ไม่ใช่ที่งาน เช่น Approach ทำไม่ได้จริง, AC ขัดกันเอง หรือถ้าทำตาม spec ตรงตัวจะได้ผลผิด ต้องแนบ SPEC_CHANGE คือข้อเสนอแก้ spec มาด้วย

  • ไม่นับเป็นรอบตีกลับ เพราะการแก้งานไม่ช่วยให้จบ
  • หน้า SPEC_ISSUE แสดงข้อเสนอ แล้วรอคุณ:
    • พิมพ์ แก้ spec ตามที่เสนอ Claude ตัวร่าง spec จะอ่าน SPEC_CHANGE เอง แล้วคุณอนุมัติ Gate 1 ใหม่
    • หรือ ทำต่อ: <คำตัดสิน> ถ้าไม่เห็นด้วย

dispute: Builder แย้งด้วยหลักฐาน

บางครั้ง reviewer พูดถึงพฤติกรรมของเครื่องมือที่ตัวเองพิสูจน์ไม่ได้ เพราะอ่านอย่างเดียว เช่นใน KS-160 Claude ยืนยันว่า Redocly จะอ่าน $ref ใต้ value ซึ่งไม่จริง ก่อนหน้านี้ Gemini ทำได้แค่สองอย่าง คือหาทางเลี่ยงจนเครื่องตรวจเงียบ หรือขอให้คุณช่วย ตอนนี้มีทางที่สาม:

python arbiter.py dispute KS-160 \
  --claim "Redocly ไม่ resolve $ref ใต้ value" \
  --prove "npx --yes @redocly/cli@1 lint --extends=recommended-strict kong-workspace/notes/policy-status-api.openapi.yaml"
  1. arbiter รันคำสั่งพิสูจน์เอง (1–3 คำสั่ง ห้ามมี | & ; < > `) เก็บ log เป็น dispute-N-pM.log และเตือนถ้าคำสั่งแก้ไฟล์งาน
  2. บันทึกลง disputes.md ข้ออ้างของ Builder ถูกติดป้าย "ยังไม่ยืนยัน" และไม่ถูกใส่ใน prompt โดยตรง
  3. Claude (Architect) ชี้ขาด จาก spec, decisions, review ล่าสุด และ log:
    ผลเกิดอะไรต่อ
    UPHOLDfinding เดิมถูก พร้อมบอกทางที่ทำตาม spec ได้ → DISPUTE_UPHELD Gemini แก้ต่อ
    REVISE_SPEClog แสดงว่าทำตาม spec ไม่ได้ → หน้า SPEC_ISSUE รอคุณ
    NEED_HUMANตัดสินจากหลักฐานไม่ได้ → NEEDS_DECISION พร้อมทางเลือก 2–3 ทาง
ทำไมไม่ให้ Gemini "ไปถาม Claude นอกรอบ" เพราะเท่ากับให้คนถูกตรวจเขียนโจทย์ให้คนตรวจ ซึ่งเป็นสิ่งที่ Arbiter ตั้งใจกันไว้ตั้งแต่แรก dispute ให้ Gemini ส่งได้แค่คำสั่ง ผลของคำสั่งเป็นข้อเท็จจริงที่เครื่องสร้าง ไม่ใช่คำอธิบายของ Gemini

workflow ข้อ 10 สั่ง Gemini ว่า ถ้าทำตาม spec หรือ finding แล้วขัดกับพฤติกรรมจริงของเครื่องมือ ห้ามหาทางเลี่ยง (เปลี่ยนวิธีจนเครื่องตรวจเงียบ, ปิด rule) ให้ใช้ dispute และหน้า FAIL ของ arbiter ก็บอกเรื่องนี้ทุกครั้ง

STALE: ไฟล์เปลี่ยนหลังรีวิว

arbiter แสดงรายชื่อไฟล์ที่เปลี่ยน และ ห้าม Gemini ย้อน, stash หรือลบไฟล์เหล่านั้นเอง (ใน KS-118 Gemini เกือบ checkout ทับรายงานของคุณ) คุณดูว่าใครแก้ ถ้าการแก้นั้นควรอยู่ในงานให้พิมพ์ review ใหม่ ถ้าไม่ควรให้บอก Gemini ว่าจะจัดการอย่างไร เอกสารนอกการ์ด (docs_allow) เปลี่ยนได้โดยไม่ทำให้ STALE

BLOCKED และ ERROR ที่เจอบ่อย

ข้อความสาเหตุทำอย่างไร
ไม่พบไฟล์ที่เปลี่ยนตาม scope_allowยังไม่ได้เขียนงาน หรือเขียนในไฟล์ที่ไม่ได้อยู่ใน scope (เช่นเอกสารนอกการ์ด)ถ้ายังไม่เขียน สั่งให้ทำต่อ ถ้าเขียนแล้ว ถาม Claude Code
spec.md ถูกแก้หลังอนุมัติ Gate 1มีคนแก้ spec โดยตรงอนุมัติ spec ใหม่ (Gemini ห้ามแก้ .arbiter/)
config ในเครื่องไม่ตรงกับฉบับที่ commitหลังรัน install หรือมีคนแก้ configคุณตรวจแล้ว git commit --no-verify เฉพาะ config/workflows
Claude อ่านการ์ดจาก Jira ไม่สำเร็จJira MCP ยังไม่พร้อม หรือ credential หมดอายุพิมพ์ ลองใหม่ ถ้าซ้ำ ให้ Claude Code ตรวจการเชื่อมต่อ
อ่านไฟล์แนบไม่ได้ชนิดไฟล์ที่ spike ยังไม่รับ เช่น .htmlส่งเป็น PDF/.docx หรือบอก path ในข้อความ

เมื่อไรควรเปิด Claude Code

  • เจอ ERROR ที่ไม่เข้าใจ หรือเห็น Gemini ทำอะไรแปลก (วนคำสั่งเดิม, เปิดอ่านไฟล์ใน .arbiter/, รัน git แปลกๆ)
  • หลังจบการ์ดหรือ spike: retro KS-xx เพื่อจดบทเรียน
  • อยากรู้ว่า Gemini ติดอะไร: Claude Code อ่าน transcript ของ Gemini ได้ที่ ~/.gemini/antigravity/brain/<id>/.system_generated/logs/

ลองตอบ

Claude ตีกลับว่า "ควรใช้วิธี X" แต่ Gemini ลองแล้ว X ทำให้ lint พัง Gemini ควรทำอะไร dispute โดยใส่คำสั่ง lint เป็น --prove ห้ามเปลี่ยนไปใช้วิธีอื่นที่ทำให้ lint เงียบโดยไม่บอกใคร
ขึ้น ESCALATE แล้วคุณพิมพ์ "ทำต่อ" เฉยๆ จะเกิดอะไร เพดานรีเซ็ตและรีวิวรอบใหม่เริ่ม แต่ไม่มีคำตัดสินให้ reviewer ยึด จึงมีโอกาสตีกลับเรื่องเดิม ควรพิมพ์ "ทำต่อ: <สิ่งที่ตัดสิน>"
dispute ครบ 2 ครั้งแล้วยังไม่จบ ครั้งที่ 3 arbiter ไม่เรียก Claude แต่ขึ้น ESCALATE ให้คุณตัดสินเลย
