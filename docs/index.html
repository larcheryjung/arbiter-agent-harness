คุณคุยกับ Gemini ในช่องแชทของ Antigravity อย่างเดียว ไม่ต้องสลับ panel ไม่ต้องจำคำสั่ง ทุกหน้าที่รอคุณจะจบด้วยบรรทัด ▶ สิ่งที่คุณต้องทำ

เริ่มงาน

งานพิมพ์ผล
การ์ด Jira/feature KS-123Claude อ่านการ์ดจาก Jira เอง (ถ้าอ่านไม่ได้จะหยุด ไม่เดา)
งานในเครื่อง ไม่มีการ์ด/feature เพิ่ม endpoint ตรวจสถานะคิวได้รหัส LOCAL-1, LOCAL-2, … โจทย์คือข้อความของคุณตามตัวอักษร

เปิดแชท Gemini ใหม่ทุกครั้งที่อัปเดต arbiter เพื่อให้โหลด workflow ฉบับล่าสุด

คุณต้องพิมพ์อะไร ที่จุดไหน

เมื่อเห็นคุณพิมพ์
NEEDS_ANSWERS คำถาม 0–5 ข้อคำตอบ (ข้อที่ไม่ตอบจะใช้ค่า [default])
READY_FOR_GATE1 specอนุมัติ Gate 1 หรือสิ่งที่อยากให้แก้ใน spec
READY_FOR_GATE2 หน้าผลตรวจอนุมัติ Gate 2 หรือสิ่งที่ต้องแก้
STALE มีไฟล์เปลี่ยนหลัง reviewดูรายชื่อไฟล์ ถ้าแก้ได้พิมพ์ review ใหม่
ESCALATE โดนตีกลับครบรอบตัดสินว่าจะ ทำต่อ + แนวทาง หรือหยุด
ERROR / BLOCKEDอ่านเหตุผล ถ้าไม่แน่ใจ ถาม Claude Code (อย่าให้ Gemini เดา)

ภาษา

spec, คำถาม และหน้า Gate 2 จะเป็นภาษาเดียวกับข้อความล่าสุดที่คุณพิมพ์ในการ์ดนั้น (โจทย์ LOCAL หรือคำตอบคำถาม) ถ้ายังไม่ได้พิมพ์อะไรใช้ภาษาไทย อยากคุยอังกฤษก็พิมพ์อังกฤษได้เลย

เอกสาร

ไฟล์ใน docs_allow commit เองได้โดยไม่ต้องมีการ์ดและไม่ต้องใช้ --no-verify ถ้าเอกสารเปลี่ยนระหว่างทำการ์ด arbiter จะไม่รวมเข้า commit ของการ์ด และบอกไว้ที่หน้า COMMITTED ให้ commit แยก

สิ่งที่คุณทำเองเท่านั้น

  • commit .arbiter/config.json (ต้อง --no-verify) ถ้า config ในเครื่องไม่ตรงกับที่ commit arbiter จะหยุดทำงาน
  • แก้ AGENTS.md / CLAUDE.md
  • deploy และงานบนระบบจริง

เมื่อไรควรเรียก Claude Code

  • หลังการ์ดจบ พิมพ์ retro KS-123 Claude Code จะอ่าน transcript ของ Gemini + โฟลเดอร์การ์ด แล้วจดลง LESSONS.md
  • เจอ ERROR ที่ไม่เข้าใจ หรือ Gemini ทำแปลก
  • จะแก้ arbiter เอง (ต้องผ่าน Gate 1/2 เหมือนงานอื่น)

ลำดับงานของ /feature

  1. Gemini arbiter spec KS-xx หรือ spec --local "..."
    Claude อ่านการ์ด Jira (หรือ intent.md) + โค้ด แล้วตอบ spec + คำถาม · การ์ด KS ต้องมีหลักฐานว่าเรียก jira_get_issue ของการ์ดนั้นสำเร็จจริง ไม่งั้น ERROR
  2. คุณ ตอบคำถาม → arbiter answer
    Claude session เดิม (resume) ปรับ spec · การตอบหรือขอแก้จะยกเลิก Gate 1 เดิมเสมอ
  3. คุณ Gate 1 → arbiter approve
    บันทึกข้อความอนุมัติ + sha256 ของ spec ถ้า spec ถูกแก้หลังนี้ ทุกขั้นถัดไปจะ BLOCKED
  4. Gemini เขียนโค้ดใน scope_allow → arbiter review
    เครื่องตรวจก่อน: scope → verify (config + spec) → tree-stable · ไม่ผ่านจะไม่เรียก Claude เลย · ผ่านแล้ว Claude อ่าน spec + diff + evidence ตัดสิน PASS/FAIL (FAIL ถ้ามี BLOCKER/MAJOR) · FAIL → Gemini แก้เอง · ตีกลับครบ 2 รอบ หรือ gate ครบ 6 รอบ → ESCALATE
  5. คุณ Gate 2 → arbiter commit
    ตรวจซ้ำเอง: spec ตรง Gate 1, โค้ดตรงกับที่ review (ไม่นับเอกสารและ .arbiter/), scope, index ไม่มีไฟล์แอบ stage · commit พร้อม trailer Arbiter-Card / Arbiter-Tree / Arbiter-Gate2
  6. Gemini ขยับการ์ดบน Jira
    Story → UAT / QA, Task → Done · การ์ด LOCAL ห้ามแตะ Jira

ข้อจำกัดที่รู้แล้ว

  • ไฟล์ใน .arbiter/ (approvals, evidence, state) agent ยังเขียนได้ การข้าม Gate 2 ตอนนี้ต้องปลอมการอนุมัติของคน ซึ่งเห็นได้ใน transcript แต่ยังไม่ถูกบล็อก
  • agent รัน approve หรือ --continue แทนคนได้ ตรวจย้อนหลังได้จาก transcript เท่านั้น
  • git commit --no-verify ข้าม hook ได้ (ตั้งใจให้คนใช้)
  • haiku ตัดสิน review ไม่สม่ำเสมอ ใช้ได้แค่ smoke test · reviewer จริงใช้ opus
  • Antigravity รันคำสั่งผ่าน powershell -Command ซึ่งทำให้ exit code ไม่ใช่ 0 กลายเป็น 1 ทั้งหมด จึงสื่อสารกับ Gemini ผ่านบรรทัด STATUS:
