เริ่มที่นี่

Arbiter คืออะไร และทำไมต้องมี

Arbiter คือ "กรรมการ" ที่ยืนอยู่ระหว่าง AI สองตัว: Gemini เป็นคนลงมือเขียนงาน, Claude เป็นคนร่าง spec และตรวจงาน ส่วนการตัดสินว่า งานผ่านหรือไม่ผ่าน ไม่ได้มาจากคำพูดของ AI ตัวไหน แต่มาจาก script ที่รันคำสั่งตรวจจริงและอ่าน exit code คุณเป็นคนกดอนุมัติแค่ 2 จุด คือก่อนเริ่มเขียน (Gate 1) และก่อนรวมงาน (Gate 2)

ประโยคเดียวที่ต้องจำ AI ทำงานได้เร็วเหมือนเดิม แต่ ห้าม AI ให้คะแนนงานตัวเอง และห้าม AI ที่ถูกตรวจเป็นคนเขียนโจทย์ให้ AI ที่ตรวจ

ในหนึ่งนาที: มีใครอยู่ในระบบบ้าง

คุณ

คุยกับ Gemini ในแชท Antigravity ช่องเดียว ตอบคำถาม กด Gate 1 กับ Gate 2 และตัดสินเรื่องที่ AI ตกลงกันไม่ได้

Gemini

คนคุมงานและลงมือเขียน เรียกคำสั่ง arbiter แล้วทำตามบรรทัด NEXT: ส่งคำพูดของคุณต่อตามตัวอักษร

arbiter (script)

กรรมการ สร้าง prompt ให้ Claude จาก template รันเครื่องตรวจ นับรอบ ตัดสินจากหลักฐาน และ commit

Claude

สถาปนิกและผู้ตรวจ ถูกเรียกแบบ claude -p อ่านได้อย่างเดียว ร่าง spec ตรวจ diff และชี้ขาดข้อโต้แย้ง

สิ่งที่คุณพิมพ์จริงๆ มีไม่กี่อย่าง

อยากทำอะไรพิมพ์ในแชท Geminiอ่านต่อ

ทำการ์ดหนึ่งใบให้เสร็จ/feature KS-xx/feature
งานเล็กที่ไม่มีการ์ด Jira/feature <เล่าโจทย์> (ได้รหัส LOCAL-n)/feature

ทุกหน้าที่รอคุณจะจบด้วยบรรทัด ▶ สิ่งที่คุณต้องทำ เสมอ ถ้าไม่เห็นบรรทัดนี้ แปลว่ายังไม่ถึงตาคุณ

ทำไมถึงต้องมี Arbiter

Arbiter เป็น harness ตัวที่ 5 ก่อนหน้านี้มี DUET, Aether Forge, AeroHarness และ Triumvirate ตัวที่ใช้กับงานจริงมีแค่ AeroHarness (signature-orchestrator KS-19 ถึง KS-58) ปัญหาที่เจอซ้ำๆ คือ:

AI รายงานผลเอง

"เทสต์ผ่านแล้ว" เป็นแค่ข้อความ ไม่มีหลักฐาน กฎ "ต้องรันจริงเท่านั้น" อยู่ใน prompt ซึ่ง AI ลืมหรือข้ามได้

คนถูกตรวจเขียนโจทย์ให้คนตรวจ

Builder เขียน architect-prompt.txt เอง จึงเลือกได้ว่าจะให้ Architect เห็นอะไร การตรวจเลยเอนตามคนทำ

กฎอยู่แค่ใน prompt

scope, Jira KS เท่านั้น, ห้ามแตะ prod ไม่มีอะไรบังคับจริง และใช้ --dangerously-skip-permissions

Arbiter แก้ด้วยการย้ายสิ่งที่สำคัญที่สุดออกจาก prompt ไปไว้ในโค้ด: เครื่องรันตรวจเอง เก็บหลักฐานเป็นไฟล์ git hook บล็อกการ commit ที่ไม่ผ่าน และ prompt ของ Claude ถูกสร้างจาก template ที่ Gemini แก้ไม่ได้

หลักแกน 7 ข้อ

  1. เครื่องเป็นคนตัดสิน ไม่ใช่ AI เล่า ผลมาจาก evidence.json และ exit code
  2. คนกดแค่ Gate 1 และ Gate 2 ช่วงระหว่างนั้นทำงานอัตโนมัติ ไม่ต้องสลับ panel
  3. คนถูกตรวจห้ามเขียนโจทย์ให้คนตรวจ Gemini ส่งแค่ตัวชี้ (รหัสการ์ด) และคำพูดของคุณตามตัวอักษร
  4. พื้นกันพังอยู่ใน git hook และ gate script ชั้นเดียวที่บังคับได้ทั้ง Gemini และ Claude
  5. harness ตัวเดียว แยกท่าตามงาน /spike สำหรับงานใหญ่ /feature สำหรับการ์ดหนึ่งใบ
  6. ส่งต่องานผ่านไฟล์ และเริ่ม context ใหม่ทุกการ์ด ไฟล์สั้นและชี้ไปที่ต้นทาง ไม่คัดลอกเนื้อหา
  7. บทเรียนต้องย้อนกลับมาแก้ harness สะดุดเมื่อไรจด LESSONS.md เจอซ้ำค่อยเพิ่มตัวตรวจ

อ่านคำอธิบายแต่ละข้อพร้อมตัวอย่างได้ที่ แนวคิดและบทบาท
