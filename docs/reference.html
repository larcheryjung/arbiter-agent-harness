กติกาใน workflow ของ Gemini (.agent/workflows/feature.md)

  1. เริ่มด้วย spec หรือ status · ใส่ --model/--effort เฉพาะเมื่อคุณสั่ง
  2. ทำตาม STATUS / NEXT เท่านั้น · เรียก arbiter ตรงๆ ห้ามห่อด้วย python -c
  3. แสดงข้อความของ arbiter ตามตัวอักษร รวมบรรทัด ▶ ห้ามสรุป ตีความ หรือแนะนำคำตอบ
  4. ส่งข้อความของคุณตามที่พิมพ์จริง
  5. ห้ามเขียน prompt ให้ Claude · ห้ามแก้ .arbiter/ · ห้ามอ่านซอร์ส arbiter
  6. แก้เฉพาะไฟล์ใน scope_allow
  7. ห้าม git checkout (รวม <tree> -- file), restore, reset, stash, clean
  8. ห้ามตัดสินเองว่าผ่าน · ห้าม commit โค้ดเอง
  9. หลัง COMMITTED ขยับ Jira ตาม lifecycle (LOCAL ห้ามแตะ)
  10. ขัดกับพฤติกรรมจริงของเครื่องมือ → dispute ห้ามหาทางเลี่ยง
  11. ข้อมูลที่ไม่มีที่มา → TODO / placeholder ห้ามแต่ง
  12. "ทำต่อ: …" / "แก้ spec: …" / "พักการ์ด" → ทำตาม NEXT · "ทำการ์ด X ต่อ" → unpark

ติดตั้ง / อัปเดตในโปรเจกต์

python C:\local-code-repo\arbiter-agent-harness\install.py --project <repo> ^
  --verify "unit=<คำสั่งเทสต์>" --docs-allow "kong-workspace/**" --docs-allow "*.md" ^
  --read-dir "C:\local-code-repo\hbs-legacy\hbs-web-core"     <-- ไม่บังคับ: repo อื่นที่ /spike อ่าน

# แล้วคน commit เอง (เฉพาะ path เหล่านี้ ไม่กวาดไฟล์อื่นที่ stage ค้างไว้)
git commit --no-verify -m "chore: install arbiter 0.3.4" -- .arbiter/config.json .arbiter/.gitignore .agent/workflows/
  • รันซ้ำได้: คง config เดิม เพิ่ม key ที่เวอร์ชันใหม่ต้องใช้ เขียน workflow ใหม่
  • โค้ดของ arbiter มีผลทันที เพราะทุกโปรเจกต์เรียกจากโฟลเดอร์เดียวกัน ส่วน workflow ต้องรัน install ใหม่ และเปิดแชท Gemini ใหม่
  • ห้ามรัน install ระหว่างที่การ์ดรอ Gate 2 เพราะ workflow ที่เปลี่ยนทำให้ tree ไม่ตรงกับที่รีวิว (STALE)

  • transcript ของ Gemini ที่ ~/.gemini/antigravity/brain/<id>/.system_generated/logs/transcript_full.jsonl (ห้ามอ่านไฟล์ credential ใน ~/.gemini)
