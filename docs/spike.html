/spike ทีละขั้น

/spike ใช้กลั่น requirement ก้อนใหญ่ที่ยังไม่ชัด ให้กลายเป็น แผนที่อนุมัติแล้ว และ รายการการ์ดบน Jira ที่แต่ละใบเข้า /feature ได้เลย ระหว่าง spike ไม่มีการเขียนโค้ดและไม่แตะไฟล์ใน repo

ใช้ /spike หรือ /feature

สถานการณ์ใช้
"หน้าบ้านอยากได้ API ดูสถานะกรมธรรม์ ช่วยคิดว่าควรเป็นยังไง มีปัญหาอะไรไหม"/spike ยังต้องคิด ถก และเลือกทาง
"ออกแบบสถาปัตยกรรมของ service ใหม่"/spike
การ์ดที่มี AC ชัด เช่น "เขียน OpenAPI spec ตาม solution ที่อนุมัติแล้ว"/feature
แก้ bug ที่รู้สาเหตุแล้ว/feature

หมายเหตุ: /spike ของ Arbiter ไม่ใช่ POC การลองของจริงเพื่อตอบคำถามเทคนิคจะเป็น track /poc แยก (ยังไม่ได้สร้าง)

ขั้นที่ 1: เริ่ม spike

เล่าโจทย์แบบที่คุณคิด ไม่ต้องเกลาให้สวย Gemini ห้ามแก้คำของคุณ และ Claude จะสรุป "ความเข้าใจโจทย์" กลับมาให้ตรวจเอง

เพิ่มข้อมูล ไม่ใช่เกลาคำ สิ่งที่ทำให้ spike ดีขึ้นจริงคือ ไฟล์แนบ เช่นโครงสร้าง view, เอกสาร requirement, ตัวอย่างข้อมูล ส่วนการให้ AI อื่นช่วย "enhance prompt" ก่อน จะทำให้การตีความของ AI ตัวนั้นติดไปกับโจทย์ และอาจทำให้ประเด็นสำคัญหายไป (ดู SPIKE-1)
ไฟล์แนบผล
.md .txt .csv .json .yml .yaml .xml .sqlคัดลอกลง inputs/ Claude อ่านตรง
.pdf และรูป (.png .jpg .gif .webp)คัดลอกลง inputs/ Claude อ่านได้ด้วยเครื่องมือ Read
.docx, .xlsxแปลงเป็นข้อความไว้คู่กัน (arbiter_extract.py)
.html, ไฟล์โค้ด และชนิดอื่นยังไม่รับ (v0.3.3) ไฟล์ที่อยู่ใน repo หรือใน read_dirs อยู่แล้ว Claude อ่านเองได้ ให้บอก path ในข้อความแทนการแนบ

ขั้นที่ 2: คุยหลายรอบ

ทุกรอบ Claude ตอบเป็น 3 ส่วน:

  • REPLY ตอบสิ่งที่คุณพูดล่าสุดตรงๆ
  • SOLUTION แผนฉบับล่าสุดใน solution.md: ความเข้าใจโจทย์, ข้อแย้งและข้อกังวล, ทางเลือก 2–3 แบบ, ที่แนะนำ, ผลกระทบ, ความเสี่ยง, สมมติฐาน
  • QUESTIONS คำถามพร้อม [default]
  • ทุกหน้าจะบอกว่า (spike SPIKE-1 · คุยไป N รอบ · ค่า Claude สะสม $X)
  • เกิน budget_usd (ค่าตั้งต้น $15) จะขึ้นคำเตือน แต่ไม่หยุดงาน
  • arbiter ต่อ session เดิมไว้ได้ 6 รอบ หลังจากนั้นจะเปิด session ใหม่ที่อ่านจากไฟล์ ซึ่งอาจลืมรายละเอียดที่คุยในแชทแต่ไม่ได้ลงไฟล์
  • ถ้าแผนเปลี่ยนหลังอนุมัติ การอนุมัติและรายการการ์ดเดิมใช้ไม่ได้ทันที
ทางลัดที่ใช้ได้ถ้าคำถามบางข้อเป็นข้อเท็จจริงที่เช็คได้ (เช่น "user readonly มีสิทธิ์ SELECT บนตารางไหม") ให้ Gemini เช็คด้วยคำสั่งจริงก่อนตอบ ไม่ต้องเดา

ขั้นที่ 3–4: อนุมัติแผน แล้ว Claude ซอยการ์ด

หลังคุณอนุมัติแผน Claude ซอยการ์ดเป็น JSON แล้ว arbiter ตรวจด้วยกฎ:

ช่องกฎ
typeStory หรือ Task
points1, 2, 3, 5, 8 และไม่เกิน max_points (8) ใหญ่กว่านี้ต้องซอยอีก
model / efforthaiku · sonnet · opus / low · medium · high (เป็นคำแนะนำ ที่จะแจ้งในหน้า Gate 1 ของการ์ด)
scope_hintpath ต้องมีอยู่จริงใน repo หรือขึ้นต้นด้วย new:
dependsต้องอ้างการ์ดที่มีอยู่ในรายการ
ac, subtasksAC แบบ Given/When/Then · ขั้นย่อย (สร้างเป็น subtask ไม่ใส่แต้ม)
Epic / Releaseไม่บังคับ Claude แนะนำ คุณตัดสิน ถ้าไม่มี Story จะแจ้งว่าไม่มีการ์ดเข้า UAT / QA

ถ้าไม่ผ่านกฎ arbiter ส่งข้อผิดกลับให้ Claude แก้ 1 รอบอัตโนมัติ (บันทึกใน cards-errors.md) ยังไม่ผ่านอีกจะ ERROR

ขั้นที่ 5–6: อนุมัติการ์ด แล้ว Gemini สร้างใน Jira

  • Gemini สร้างการ์ดใน project KS เท่านั้น ใช้ชื่อ ประเภท แต้ม และ description จาก cards.md ตามตัวอักษร
  • ผูก epic และ fix version ถ้ามี และสร้าง subtask
  • รัน spike link ด้วยรหัสจริงทุกตัว arbiter จะ:
    • ตรวจว่าครบและไม่ซ้ำ
    • บันทึก jira-map.json
    • commit โฟลเดอร์ spike (ไม่มีโค้ด hook จึงผ่าน)
    • ดึงการ์ดทุกใบออกจาก Backlog ขึ้นบอร์ด ยกเว้น Epic
ทำไม arbiter ต้องดึงการ์ดขึ้นบอร์ดเอง การ์ดที่สร้างผ่าน API จะไปอยู่ใน Backlog compartment เสมอ แม้เปลี่ยนเป็น Ready for Dev แล้ว และการ์ดที่ปิดจาก Backlog จะหายจากบอร์ด ก่อน v0.3.2 เรื่องนี้เป็นแค่คำขอใน NEXT ซึ่ง Gemini ข้ามไปใน SPIKE-1 ตอนนี้ arbiter เรียก Jira Agile API เอง ถ้าไม่สำเร็จจะขึ้น ⚠ พร้อมลิงก์ให้ลากเอง

ลองตอบ

ควรให้ Gemini ช่วยเกลา requirement ให้สวยก่อนส่ง spike ไหม ไม่ควร เพราะจะทำให้การตีความของ Gemini ติดไปกับโจทย์ รอบคำถามของ spike ทำหน้าที่ทำโจทย์ให้ชัดอยู่แล้ว ถ้าอยากให้ดีขึ้นให้เพิ่มไฟล์แนบ
อนุมัติแผนไปแล้ว แต่อยากเปลี่ยนทางเลือก พิมพ์สิ่งที่อยากเปลี่ยนได้เลย Gemini ส่งด้วย spike answer ถ้าแผนเปลี่ยน การอนุมัติแผนและรายการการ์ดเดิมจะถูกยกเลิก แล้วคุณอนุมัติใหม่
การ์ดจาก spike แนะนำ "sonnet · medium" จะถูกใช้ตอนไหน ตอนรีวิวและ dispute ของการ์ดนั้น โดยแจ้งในหน้า Gate 1 ก่อน ถ้าคุณไม่ทักในคำอนุมัติก็ใช้ตามนั้น ส่วนการร่าง spec ใช้ Opus · High เสมอ
