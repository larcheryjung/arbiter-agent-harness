# /feature KS-xx  หรือ  /feature <โจทย์>

1. เริ่มงาน
   - ถ้าผู้ใช้พิมพ์ตามหลัง /feature แค่รหัสการ์ด (เช่น KS-12 หรือ LOCAL-3): รัน `python "{{ARBITER}}" spec <รหัส>` ถ้าการ์ดมี spec อยู่แล้ว ให้รัน `python "{{ARBITER}}" status <รหัส>` แทน
   - ถ้าผู้ใช้สั่ง model หรือ effort เองตอนเริ่มการ์ด (เช่น "ใช้ sonnet medium") ให้เติม `--model <haiku|sonnet|opus|fable> --effort <low|medium|high>` ต่อท้ายคำสั่ง `spec` ห้ามเลือกเอง (ไม่สั่ง = spec ใช้ opus · high ส่วนขั้นรีวิว arbiter แจ้งในหน้า Gate 1 แล้วผู้ใช้ทักได้ในคำอนุมัติ)
   - ถ้าผู้ใช้พิมพ์เป็นโจทย์: รัน `python "{{ARBITER}}" spec --local "<ข้อความทั้งหมดตามที่ผู้ใช้พิมพ์ ห้ามแก้>"` arbiter จะตั้งรหัส LOCAL-n ให้เอง
2. ทุกครั้งที่รัน arbiter ให้อ่านบรรทัด `STATUS:` และทำตามบรรทัด `NEXT:` เท่านั้น (exit code ไม่ได้บอกผล) เรียก `python "{{ARBITER}}" ...` ตรงๆ ห้ามห่อด้วย `python -c` / subprocess (ข้อความไทยพังและผลหาย)
3. ข้อความที่ arbiter ให้แสดงต่อผู้ใช้ ให้แสดงตามตัวอักษรรวมถึงบรรทัด `▶ สิ่งที่คุณต้องทำ` ห้ามสรุปหรือแปลใหม่ ห้ามอธิบายสาเหตุ ห้ามตีความ และห้ามแนะนำคำตอบแทนผู้ใช้ ถ้าผู้ใช้ถามความเห็นเอง ให้บอกชัดว่าเป็นความเห็นของ Gemini
4. ข้อความของผู้ใช้ที่ต้องส่งให้ arbiter ให้ส่งตามที่พิมพ์จริง ห้ามแก้ ห้ามเติม
5. ห้ามเขียน prompt หรือคำอธิบายส่งให้ Claude เอง ห้ามแก้ไฟล์ใน `.arbiter/` และห้ามเปิดอ่านหรือแก้ซอร์สของ arbiter (โฟลเดอร์ที่มี `arbiter.py`)
6. ตอนเขียนโค้ด แก้เฉพาะไฟล์ใน `scope_allow` ของ spec ถ้าจำเป็นต้องแก้นอก scope ให้หยุดถามผู้ใช้
7. ห้ามใช้ `git checkout` (รวมถึง `git checkout <commit/tree> -- <ไฟล์>`), `git restore`, `git reset`, `git stash`, `git clean` และห้ามลบหรือย้อนไฟล์ที่การ์ดนี้ไม่ได้สร้างหรือแก้ ถ้าเจอไฟล์เปลี่ยนที่ไม่รู้ที่มา ให้หยุดถามผู้ใช้
8. ห้ามตัดสินเองว่างานผ่าน ผลผ่านหรือไม่ผ่านมาจาก `arbiter review` เท่านั้น ห้าม commit โค้ดเอง ให้ใช้ `arbiter commit` (ยกเว้นเอกสารที่ arbiter แจ้งว่ายังไม่ได้ commit ให้ commit แยกได้เมื่อผู้ใช้สั่งเท่านั้น)
9. หลัง `STATUS: COMMITTED` ให้ทำตาม `NEXT:` (การ์ด KS ขยับบน Jira ตามกฎ lifecycle ส่วนการ์ด LOCAL ไม่มีบน Jira ห้ามแตะ Jira)
10. ถ้าทำตาม spec หรือ finding ของ reviewer แล้วขัดกับพฤติกรรมจริงของเครื่องมือ (lint, framework, library) ห้ามหาทางเลี่ยง เช่น เปลี่ยนวิธีจนเครื่องตรวจเงียบ หรือปิด rule ให้รัน `python "{{ARBITER}}" dispute <รหัส> --claim "<ข้ออ้าง 1 บรรทัด>" --prove "<คำสั่งที่พิสูจน์>"` (`--prove` ใส่ได้ถึง 3 ครั้ง) arbiter จะรันคำสั่งเองแล้วให้ Claude ชี้ขาด
11. ข้อมูลที่ไม่มีที่มาใน spec โค้ด หรือเอกสาร (ชื่อ license, URL, อีเมล, hostname, ความหมายทางธุรกิจ) ห้ามแต่งเอง ให้ใส่ `TODO` หรือ placeholder ที่เห็นชัดว่ายังไม่ใช่ของจริง
12. ผู้ใช้พิมพ์ "ทำต่อ: ...", "แก้ spec: ..." หรือ "พักการ์ด" ให้ทำตาม `NEXT:` ของหน้าล่าสุด ส่ง "ทำการ์ด <รหัส> ต่อ" ด้วย `unpark` ข้อความของผู้ใช้ส่งตามที่พิมพ์จริงเสมอ
