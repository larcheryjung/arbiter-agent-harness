# /spike KS-xx  หรือ  /spike <requirement และ/หรือไฟล์แนบ>

1. เริ่มงาน
   - ถ้าผู้ใช้พิมพ์แค่รหัสการ์ด (เช่น KS-12 หรือ SPIKE-3): รัน `python "{{ARBITER}}" spike new <รหัส>` ถ้ามี spike นี้อยู่แล้ว ให้รัน `python "{{ARBITER}}" spike status <รหัส>` แทน
   - ถ้าผู้ใช้พิมพ์ requirement: รัน `python "{{ARBITER}}" spike new --text "<ข้อความทั้งหมดตามที่ผู้ใช้พิมพ์ ห้ามแก้>"` ถ้าผู้ใช้แนบไฟล์ ให้เพิ่ม `--file "<path>"` ทีละไฟล์ (มีแต่ไฟล์ก็ได้) arbiter จะตั้งรหัส SPIKE-n ให้เอง
2. ทุกครั้งที่รัน arbiter ให้อ่านบรรทัด `STATUS:` และทำตามบรรทัด `NEXT:` เท่านั้น (exit code ไม่ได้บอกผล)
3. ข้อความที่ arbiter ให้แสดงต่อผู้ใช้ ให้แสดงตามตัวอักษรรวมถึงบรรทัด `▶ สิ่งที่คุณต้องทำ` ห้ามสรุปหรือแปลใหม่ ห้ามตอบแทน Claude ห้ามตีความ และห้ามแนะนำคำตอบแทนผู้ใช้ ถ้าผู้ใช้ถามความเห็นเอง ให้บอกชัดว่าเป็นความเห็นของ Gemini
4. spike เป็นการคุยหลายรอบ ทุกข้อความของผู้ใช้ (ตอบ ถามกลับ แย้ง ขอแก้) ให้ส่งต่อด้วย `spike answer` ตามที่พิมพ์จริง ห้ามแก้ ห้ามเติม ยกเว้นข้อความที่อนุมัติแผนหรืออนุมัติการ์ด ให้ใช้ `spike approve`
5. ห้ามเขียน prompt หรือคำอธิบายส่งให้ Claude เอง ห้ามแก้ไฟล์ใน `.arbiter/` และห้ามเปิดอ่านหรือแก้ซอร์สของ arbiter (โฟลเดอร์ที่มี `arbiter.py`)
6. spike ไม่มีการเขียนโค้ด ห้ามแก้ไฟล์ใดๆ ใน repo ระหว่าง spike
7. ตอน `STATUS: APPROVED_CARDS` ให้สร้างการ์ดใน Jira project KS เท่านั้น ตาม `NEXT:` ทุกตัวอักษร (ชื่อ ประเภท แต้ม description ตามไฟล์ ห้ามแก้หรือสรุป) แล้วรัน `spike link` ด้วยรหัสจริงที่ได้
8. หลัง `STATUS: SPIKE_DONE` ให้ทำตาม `NEXT:` แล้วจบ การ์ดแต่ละใบจะเริ่มด้วย /feature เมื่อผู้ใช้สั่ง
